# Security dan privasi

Threat model mencakup penyalahgunaan sesi customer/staff, akses lintas order, bukti transfer palsu, upload berbahaya, selisih rekonsiliasi, replay provider, percobaan oversell, dan exposure secret oleh log atau backup. Privilege dibatasi dari reverse proxy sampai policy bisnis dan IAM storage.

## Identitas, sesi dan akses

- Hanya role Spatie sistem `web:super_admin` dengan sesi STAFF aktif dapat melewati grant permission bisnis yang sudah terdaftar. Tidak melewati CSRF, ownership, step-up atau batas sesi. Log Viewer dan OmniDB mengharuskan role sistem ini, terlepas dari assignment permission biasa. Pembukaan konsol tercatat di audit per sesi. Tidak ada URL storefront atau konsol produksi.

- Sanctum SPA session dibatasi surface CUSTOMER/STAFF. Gunakan Secure dan HttpOnly untuk session cookie, SameSite=Lax, host-only, idle TTL customer 7 hari dan staff 30 menit dengan maksimum absolut 12 jam untuk staff (ASSUMPTION). Cookie CSRF dapat dibaca client sesuai Sanctum, dan mutasi memerlukan X-XSRF-TOKEN serta request origin yang benar. Cookie dipisahkan oleh host; proxy mempercayai forwarded host hanya dari edge yang dikelola.
- Password 12–128 karakter, hash Argon2id, rehash saat parameter berubah, generic error untuk login/reset. Rate limit login berdasarkan key IP+identifier dan limit IP terpisah, baseline 5 kegagalan/menit per key dan 30/menit IP. Reset dan email verifikasi single-use, token hash, TTL 30/60 menit; challenge throttle. Challenge untuk email disimpan terenkripsi di payload outbox dengan TTL dan denormalisasi yang dibatasi. Worker menghapus material setelah delivery final. Sesi baru setelah login, re-auth dan MFA. Reset password, disable dan perubahan keamanan mencabut sesi terkait. Revoke per device memakai opaque reference, bukan session ID mentah.
- Google OAuth authorization code melalui Socialite, state random single-use terkait session, callback URL allowlist, verifikasi provider issuer, audience, subject dan email_verified memakai provider flow. Akun customer baru memakai email verified. Jika email sudah ada dan subject belum terhubung, buat challenge singkat dan minta pemilik login serta konfirmasi password atau selesaikan reset email lebih dahulu. Link tidak otomatis berdasar kesamaan email. Rotasi sesi dan kirim pemberitahuan. Staff tidak dapat login Google lewat storefront.
- Staff memiliki akun terpisah, undangan terbatas waktu, TOTP mandatory, recovery codes encrypted at rest dan ditampilkan sekali. Operator recovery memverifikasi identitas, revoke seluruh sesi dan enroll ulang. Endpoint staff general me/sessions dibatasi surface staff. Permission Spatie dan Laravel policy dicek di route dan action. Scope parent file dan ownership menghasilkan 404 untuk customer lain. Admin menu hanya refleksi izin.
- Step-up dengan password dan kode TOTP segar melalui endpoint staff; re-auth/MFA berlaku maksimal 10 menit untuk role, bank, refund, stock correction berisiko dan recovery. Maker-checker untuk settlement manual exception dan refund, reviewer/capturer berbeda dari eksekutor/finalizer kecuali tim bisnis menyetujui prosedur darurat ter-audit melalui operator. Finance cocokkan mutasi rekening. Review biasa pun menyimpan actor/reason dan nilai transaksi.
- CORS hanya exact origins dev yang terdaftar jika mode transisi membutuhkan; produksi same-origin, tanpa wildcard credentials. Edge rate limit burst dan Laravel keyed threshold lebih spesifik. Baseline upload 10/menit per akun dan checkout 10/menit per akun (ASSUMPTION). Expose Retry-After.

## Input, content dan file

- FormRequest whitelist struktur, field serta enum. DTO mencegah mass assignment. Bind parameter SQL dan map filter/sort ke daftar field. Content rich text disanitasi sebelum penyimpanan dan render, escape default Vue, CSP default-src self dengan allowlist layanan/asset, frame-ancestors deny, no-sniff, Referrer-Policy strict-origin-when-cross-origin. Hindari raw template dan script markup. URL pelanggan ditampilkan sebagai link dengan rel aman, tanpa download SSR/terusan server.
- Bucket publik hanya untuk katalog siap tayang. MinIO private untuk payment proof, request attachments, return/refund evidence, invoice PDF dan shipment attachments. Identity service storage per environment dan purpose terpisah. Original filename tidak dipakai sebagai key; UUID/ULID + prefix koleksi. Transport TLS, at-rest encryption platform dan backup, tanpa daftar object publik.
- Input multipart dibatasi 25 MiB di edge. Katalog image JPEG/PNG/WebP ≤ 8 MiB, re-encode dan strip EXIF. Dokumen proof/attachment PDF, JPEG, PNG, WebP ≤ 10 MiB. Return video MP4 ≤ 20 MiB, maksimum 1 video/kasus. Default maksimum 5 file privat per case/koleksi (ASSUMPTION). Sniff MIME, cek extension, magic/decoder dan ukuran, tolak archive, SVG dan executable. Quarantine private → scan anti-malware (ClamAV service atau managed equivalent) → READY atau REJECTED. Gagal scan tetap privat dan queued; cleaner menghapus orphan. File diterima action bisnis hanya READY dan cocok owner/collection. PDF internal render lokal tanpa akses remote resource.
- Koleksi upload allowlist owner: product/variant untuk catalog_media, payment untuk payment_proof, request_order untuk request_attachment, return untuk return_evidence, refund untuk refund_evidence/refund_transfer_proof, payment_reconciliation untuk reconciliation_proof, shipment untuk shipment_attachment. Invoice PDF dihasilkan worker, geografi admin memakai collection region_import dari staging dengan CSV ≤ 5 MiB dan parser streaming. Parent action dan actor menentukan permission. URL unduh private TTL lima menit, metode GET dan key spesifik, Content-Disposition attachment, no-store, audit signed-URL issuance. Signed URL yang telah diterbitkan dapat berlaku sampai TTL; pencabutan darurat purge object/key atau temporary access.
- TASK-003: status READY bukan izin publikasi; semua hasil scan tetap di bucket privat. Modul Catalog baru boleh menyalin media READY ketika produk dipublikasikan ke prefix publik `published/`. Pada kedua surface, `files.surface.customer`/`files.surface.staff` harus memeriksa sesi melalui Identity. Modul parent mendaftarkan `FileOwnerPolicy` di konfigurasi `stored_files.owners`: owner_ref diselesaikan server-side dengan cek ownership/permission; konfigurasi kosong berarti akses ditolak. Action bisnis memanggil `StoredFiles::requireReady` di dalam transaksi parent setelah otorisasi.
- Callback provider hanya pada adapter terdaftar. Verifikasi HMAC/signature dengan raw bytes, replay window sesuai kontrak dan event ID durable. Key rotation aktif dan previous terbatas waktu. Batasi provider base URL dan route egress. Jalankan replay melalui system/operations dengan audit.

## PII, secret, audit dan tanggap insiden

| Aset | Kontrol dan retensi rancangan |
|---|---|
| PII pembeli | Minimalkan telemetry, alamat ter-snapshot pada order dan dikirim ke kurir hanya bila perlu. Restrict role, log masked. Permintaan penghapusan memisahkan akun dan dokumen yang wajib dipertahankan. |
| Bukti dan invoice | Gambar bukti private, akses sesuai policy. Retensi finansial final setelah review legal Q-01/Q-04; target awal bukti 2 tahun dan invoice 5 tahun (ASSUMPTION), legal hold mencegah purge. |
| Sesi/credential | Secret hanya vault/platform, .env.example placeholder, rotate sesudah personel berubah atau insiden. Session log metadata minim. Provider token/server creds tidak pernah masuk frontend build. |
| Audit | Append-only dengan actor, action, entity, before/after redacted, IP, UA, timestamp dan request ID. Payment approve/recover, refund, return, adjustment, perubahan harga/status, role, bank, provider, dan file sensitif wajib audit. Akses log di-audit. |
| Log dan observability | Structured JSON stdout, correlation ID, idempotency conflict dan code, queue retries, provider latency. Buang body mentah, password, cookie, challenge, bukti dan nomor rekening utuh. Retensi operasional awal 30 hari (ASSUMPTION), role operator terpisah. |
| Incident | Isolasi surface/provider, revoke tokens, rotate secret, pertahankan audit redacted, rekonsiliasi order/dana/stok, dan gunakan prosedur restore bila perlu. |

Operator memberi alert pada brute-force spike, outbox lag, invalid webhook signatures, role change, duplicate bank reference dan percobaan unduh tanpa izin. Rilis melewati SCA untuk dependensi/image, lint, test authorization/CSRF, smoke private bucket, pembatasan CORS, dan review perubahan permission.
