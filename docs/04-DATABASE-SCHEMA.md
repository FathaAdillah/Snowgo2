# Database schema

PostgreSQL 16. Skema logis ini menentukan migration yang akan dibuat setelah persetujuan. [State machine](06-BUSINESS-FLOWS.md) menjadi katalog CHECK untuk kolom State. ERD logis menunjukkan hubungan utama; FK pada kamus berikut lebih lengkap. [ERD](diagrams/erd.md)

## Konvensi fisik

- Default tabel memiliki id bigint GENERATED BY DEFAULT AS IDENTITY PK, created_at dan updated_at timestamptz NOT NULL DEFAULT now(). Tabel yang mendeklarasikan PK sendiri menggantikan id default. Append-only tables menghilangkan updated_at. Sessions, password_reset_tokens, failed_jobs dan pivot Spatie memakai hanya timestamp yang tertera pada katalog kolom, sesuai adapter Laravel.
- FK default ON DELETE RESTRICT dan diindeks (lewati jika sudah merupakan prefix indeks lain). Pivot role permission memakai CASCADE. Entity transaksi tidak dihapus; master yang diarsip memakai status, active atau deleted_at sesuai tabel. Hapus data pribadi via kebijakan retensi dan anonimisasi. FK polymorphic menggunakan allowlist, policy dan reconciler, tanpa join lintas model.
- Nominal settlement bigint whole-IDR, integer rupiah dengan batas aplikasi 0..1.000.000.000.000. Currency IDR untuk semua settlement. Hitung diskon/pajak di server dengan integer dan half-up per baris. Rate dan harga supplier di quotation bersifat informasi saja. JSON klien memakai integer pada rentang tersebut; jangan melakukan kalkulasi uang dengan float. Seluruh kolom nominal default CHECK >= 0; delta ledger integer bertanda. Kuantitas dan counter umumnya CHECK >= 0 kecuali delta.
- U = UNIQUE; PU = partial UNIQUE; I = indeks B-tree; C = CHECK; GIN = indeks GIN. DDL eksplisit wajib untuk invariant lintas kolom. Invariant lintas tabel diverifikasi di action owner di bawah lock. PostgreSQL citext extension untuk email/coupon. Nama database snake_case. Waktu UTC, format ISO-8601, UI WIB.
- Nomor order, preorder, request, quotation, invoice, payment, shipment, refund, return dan batch memakai satu sequence per aggregate; format PREFIX-YYYYMMDD-NNNNNN, counter tidak reset harian, padding minimum enam digit dengan unique index. Gaps normal setelah rollback. PK tidak diekspos kepada pembeli. Public ID ULID untuk file, checkout, quote shipping, consent dan inbox; entitas publik transactional lain memakai business number. Customer address/cart item memakai ID opaque berbasis ULID terpisah sebagaimana aturan kolom di bawah.
- Tags pada kolom: NOT NULL adalah default, tanda ? berarti nullable, ! unique, ^ PK. Default dicantumkan eksplisit; tanpa default artinya disuplai writer. UUID/ULID dihasilkan aplikasi. Data transaksi besar memakai page/cursor, index sesuai query profil.
- Upload bukti payment memiliki row khusus. Request attachments, return evidence, shipment attachments dan invoice PDF memakai stored_files dengan collection allowlisted dan owner yang sesuai. File return proof transaksi refund berelasi langsung dari refund_transactions. Bukti refund yang disertakan pembeli menggunakan collection refund_evidence.

## Invariant antar-tabel

| Area | Invariant |
|---|---|
| Checkout | Lock cart/version, reserve semua grup dan insert order/address/invoice/outbox satu transaksi; cart sukses CONVERTED. RTS satu per checkout; PO satu per campaign. Gunakan partial unique checkout_id untuk RTS dan (checkout_id,campaign_id) untuk PO. order method menentukan FK wajib. |
| Quote | Kunci cart/order, quote shipping belum terpakai, context hash dan expiry valid. Shipping consent PO/RO mengikat tarif, layanan, seluruh charge, paket dan revision; pembeli menerima sebelum issue. Partial unique satu consent PROPOSED per order dan scope paket. Invoice covered_qty disimpan untuk baris yang memuat unit payable. |
| Ledger | Saldo level dan movement konsisten; semua mutasi di bawah lock/conditional update. Expiry hanya ACTIVE, tidak menyentuh committed. |
| Pengadaan | Qty batch kumulatif ≤ qty order setelah cancellation; receipt dan failure tidak melebihi qty batch. Preorder confirmed_qty historis, tidak otomatis dijual ulang setelah supplier failure. |
| Dana | Lock order lalu invoice/payment; applied allocations maksimal sisa invoice, capture sama total allocations; satu transfer bank adalah satu receipt logis. payment_reconciliations dipakai untuk late/duplicate/mismatch dan menyimpan referensi yang sama dengan payment hanya saat APPLIED, dalam transaksi yang sama. Controller settlement wajib mengunci row bank/account dan memeriksa kedua tabel agar referensi bank unik lintas jalur. |
| Refund | Lock order dan seluruh payment_allocations terkait secara terurut. Capture dikurangi refund selesai serta approved/processing/failed unresolved menjadi cap tersedia; produk dan qty harus milik order, bukti valid. Reference satu transfer dapat membagi beberapa allocations dalam satu refund, dikunci dan diverifikasi terhadap seluruh referensi. |
| Shipping | Cegah dua shipment aktif mengklaim qty yang sama; lock order item dan cek jumlah paket non-cancelled. Standard dispatch hanya untuk eligible qty. Replacement mengacu return/resolusi agar qty pengganti tidak menduplikasi fulfillment asal. |
| Koreksi | Invoice issued immutable kecuali status/paid_at. Nominal berubah melalui void + revised snapshot atau dokumen tambahan, tanpa menyunting histori. |
